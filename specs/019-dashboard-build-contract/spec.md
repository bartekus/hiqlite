# 019: Adopt the dashboard build contract and measure its drift

## 1. Purpose

W-13 asks for one thing: "a rebuild under recorded toolchain and lockfile inputs
compares deterministically and drift fails the check". OD-2 had already decided
the surrounding question, that the built bytes stay committed.

Nobody had run the rebuild. This spec runs it, twice from clean, and reports what
came back. Both halves of the closing condition turn out to be false today, for
two independent reasons, and the first of them makes the check W-13 describes
unbuildable as specified until a one-line configuration change is made.

**It is an adoption.** Nothing is repaired, no artifact is rebuilt into the tree,
and no check is added. `hiqlite/static` is byte-identical to what it was before
this spec was written, which section 4 states as a verified fact and not an
intention.

## 2. Territory

**Establishes** the five build-configuration files of the `dashboard` package:
`svelte.config.js`, `vite.config.ts`, `tsconfig.json`, `playwright.config.ts` and
`package.json`. These are what "recorded toolchain and lockfile inputs" means.

**Does not claim** `hiqlite/static` itself. It is generated output, F-016 records
that its twelve uncompressed `.js` files inflate the coverage denominator as
unclaimed source, and W-14 is the blocked row that would remove them from it.
Claiming generated bytes to improve a number is the exact move `005` section 2.1
exists to argue against. D-2 records this.

**Does not claim** `dashboard/package-lock.json`, for the same reason: it is
resolver output. B-1 names it as an input and the acceptance block pins its
presence.

**Extends** `000` on the `justfile`, whose `build ui` recipe and its commented-out
line inside `verify` are what B-2 is about, without modifying either; and `005`
on the findings register and the adoption plan.

**Depends on** `018`, which claims both sides of what this configuration builds.

## 3. Behavior

### B-1. The build contract, stated

`npm run build` is `vite build`. `svelte.config.js` configures
`@sveltejs/adapter-static` with `pages` and `assets` both `../hiqlite/static`,
`fallback: null`, `strict: true` and **`precompress: true`**, which is where the
`.br` and `.gz` siblings come from: every emitted file is written three times.
`paths.base` is `/dashboard`, matching the nest `018` B-1 describes, and a
Content-Security-Policy is set unless `DEV_MODE=true`, allowing
`wasm-unsafe-eval` for the proof-of-work solver and `self` for everything else.

`hiqlite/src/dashboard/static_files.rs:15-17` then embeds that directory with
`rust-embed` `#[folder = "static"]`, so the committed bytes are what a built
binary serves. The inputs are therefore: `dashboard/src`, the five configuration
files, `package-lock.json`, and the node and npm versions, of which only the
first three are recorded in the repository.

### B-2. Nothing builds it, and the recipe that would is commented out

`justfile:146-160` (`build ui`) removes `hiqlite/static`, runs `npm run build`
and `git add`s the result. `justfile:224-226` is the `verify` recipe, whose first
line is the commented-out `#just build ui` with the note "we don't want to
rebuild the UI each time because it's checked into git". Neither
`.github/workflows/code_style.yaml` nor `spec-spine.yaml` builds the dashboard.

So the artifact is refreshed only when a human remembers to run one recipe, and
nothing anywhere compares it to its source. That is F-012, recorded on
2026-09-19. Section 4 is what happens when the comparison is finally made.

### B-3. The output is content-addressed, which is what makes drift detectable
### at all

Vite names every chunk after a hash of its content
(`_app/immutable/chunks/<hash>.js`), and `precompress` derives the two siblings
from it. A byte-level drift check is therefore mostly a file-name comparison: if
any source byte changes, chunk names change.

That property is what W-13's closing condition assumes. KD-1 is the input that
breaks it.

## 4. Evidence: the rebuild, run

**Performed 2026-09-21 on this tree**, with node `v24.6.0` and npm `11.5.1`, from
the committed `package-lock.json` via `npm ci` (exit 0).

**Result 1: two clean builds from identical inputs do not agree.**
`hiqlite/static` was removed, `npm run build` was run, every file was hashed;
then the directory was removed again and the whole thing repeated. Both runs
emitted 64 files. The two hash lists **differ**: `_app/version.json`, `index.html`
and their compressed siblings differ in content, and `entry/app.*.js`,
`entry/start.*.js`, `nodes/1.*.js`, `nodes/2.*.js` and one chunk differ in
**name**, because their content hash changed.

The cause is one file. `_app/version.json` is `{"version":"1790021962128"}`, a
millisecond epoch: SvelteKit's `kit.version.name` defaults to `Date.now()`, and
`svelte.config.js` does not set it. That value is embedded in the client entry,
so it changes the entry's content, its content hash, its file name, and then
every file that references the name. KD-1.

**Result 2: the committed artifact does not come from this source at this
lockfile.** A clean build emits **64** files; `git ls-files hiqlite/static`
lists **55**. The difference is not a hash rename: the fresh build emits
`_app/immutable/assets/spow-wasm_bg.C-R_-59b.wasm` and its two compressed
siblings, which have no counterpart in the committed set at all, and five
committed chunk names (`DYl5dUZ5`, `HS78R7GZ`, `Rzvk3oo4`, `ucR_hd6Y`,
`yhtOcEv9`) have no counterpart in the build. A differing file **count**, and a
whole asset present on one side only, cannot be explained by KD-1's timestamp.
KD-2.

**Result 3, found by doing the above: building the dashboard breaks
`just spine-check`.** `npm run build` creates `dashboard/.svelte-kit`, which
`dashboard/.gitignore:5` ignores. The pinned indexer's npm package walk does not
read that file: with the directory present, `spec-spine index coverage` reports a
denominator of **292** instead of 236, having taken 56 generated `.js` and `.d.ts`
files as package source, and the committed index is stale. Deleting the directory
returns it to 236 exactly. KD-3.

**The tree was restored and the restoration was verified.** `hiqlite/static` was
deleted and checked out again, and its 55 files hash identically to the snapshot
taken before any of this began; `dashboard/.svelte-kit` was removed. `git status`
shows nothing under either path.

**What this does not establish.**

- **Which input drifted.** KD-2 says the committed bytes and the current source
  disagree; it does not say whether `dashboard/src` moved forward, the toolchain
  changed, or a dependency did. Determining that needs the build provenance
  nobody recorded, which is the point.
- **That the committed dashboard is broken.** It is not: `018`'s
  `a_known_asset_is_served_with_its_cache_headers` serves `index.html` out of the
  committed bytes, and the shipped UI works. The finding is that it is not
  reproducible, not that it is wrong.
- **Determinism on another machine or another node version.** Two runs, one
  machine, one toolchain. That is enough to prove **non**-determinism, which is a
  negative claim and needs only one counterexample; it says nothing about how
  much worse it gets across machines.
- **Whether the pinned tool can be made to ignore `.svelte-kit`.** KD-3 measures
  the interaction; whether `resolver_exclusions` or any other key reaches it was
  not probed, and W-14 records that the equivalent question for `hiqlite/static`
  has no answer at this pin.
- **Anything about `@sveltejs/kit`'s own guarantees**, which are named as pinned
  dependency behavior.

## 5. Known defects

Recorded as found, none repaired. Each is also filed in
`standards/spec/findings-register.md`.

**KD-1. The dashboard build is not reproducible, and one line is why** (F-092).
`svelte.config.js` does not set `kit.version.name`, so SvelteKit defaults it to
`Date.now()` and writes `_app/version.json` as `{"version":"<epoch millis>"}`.
That value reaches the client entry, so two builds one second apart produce
different content, different content hashes, different file names for the entry,
both route nodes and at least one chunk, and different `index.html`.

Consequence, and the reason this blocks a row rather than merely annoying
someone: **the drift check W-13 asks for cannot be built as specified.** A
byte-comparison between a fresh build and the committed artifact reports a
difference every time, so it can neither pass nor be believed when it fails. The
fix is to set `kit.version.name` to a deterministic value, for example the crate
version or the commit sha, after which the comparison becomes meaningful.

**Observed by execution**: two clean builds from identical inputs, hashed and
diffed, with the differing paths listed in section 4.

**KD-2. The committed artifact is not what this source builds** (F-093). A clean
build emits 64 files; 55 are committed. The fresh build emits
`_app/immutable/assets/spow-wasm_bg.C-R_-59b.wasm` plus its `.br` and `.gz`,
which the committed set does not contain in any name, and five committed chunk
names have no counterpart in the build.

Consequence: what ships in the binary was built from inputs that are no longer in
the tree, so a reviewer reading `dashboard/src` is not reading what a user runs,
which is exactly the consequence F-012 predicted in the abstract on 2026-09-19.
This is the first measurement of it. **Observed by execution**; which input
drifted is not established (section 4).

**KD-3. A local dashboard build inflates the coverage denominator and stales
the committed index** (F-094). `npm run build` creates `dashboard/.svelte-kit`,
git-ignored by `dashboard/.gitignore:5` and counted anyway: the pinned indexer
walks the declared npm package by extension and does not consult `.gitignore`, so
its 56 generated `.js` and `.d.ts` files enter the denominator as unclaimed
source. Measured: 292 with the directory present, 236 without, the same tree
otherwise.

Consequence, and why it belongs in this spec rather than as a note: the drift
check W-13 asks for **must** build the dashboard, and on this tool a build makes
`spec-spine index coverage` disagree with the committed shards. So the check
cannot be added without either excluding `.svelte-kit` or cleaning it afterwards,
and a contributor who runs `just build ui` today sees `just spine-check` fail for
a reason unrelated to anything they changed. CI never builds the dashboard, so
the committed index is unaffected in practice, which is why this went unnoticed.
Same family as F-016, which is blocked on the same missing exclusion capability
(W-14). **Observed by execution.**

**Not a finding, and stated so it is not read as one.** The build itself is
healthy: `npm ci` and two `npm run build` runs all exited 0, with no errors and
no type failures. The problem is provenance, not correctness.

**Retained without change.** F-012, whose consequence is now measured rather than
argued, and F-016, which records that the twelve uncompressed `.js` files under
`hiqlite/static` sit in the coverage denominator as unclaimed source and is
blocked on the pinned tool (W-14).

## 6. Resolved decisions

**D-1 (2026-09-21, the artifact is not rebuilt and no check is added).** The
temptation is to commit the fresh build, which would make the tree
self-consistent for exactly as long as it takes the next timestamp to differ.
KD-1 has to be fixed first, or the same divergence returns on the next build and
the check still cannot be written. Adding the check is also a CI change, which is
`000`'s and W-19's, and enabling a refusal is an enforcement decision.

**D-2 (2026-09-21, `hiqlite/static` is not claimed).** It is generated output.
F-016 records that its uncompressed `.js` files inflate the denominator, and W-14
is the blocked row for removing them; claiming them would raise the coverage
number by twelve while adding no statement about behavior, which is the move
`005` section 2.1 was written to prevent. The five configuration files that
produce it are claimed instead, which is where a contract can actually live.

**D-3 (2026-09-21, the rebuild is reported as a dated measurement).** No test
re-runs it: doing so would need node, npm and a network install inside an
acceptance block, which would make `just spine-verify 019` require a toolchain no
other spec does. The acceptance block pins the configuration facts KD-1 depends
on instead, so if `kit.version.name` is ever set, the assertion that it is absent
fails and this spec is forced to be revisited.

**D-4 (2026-09-21, OD-2 is not reopened).** Keeping the bytes committed remains
the decision. Nothing here argues against it; KD-1 and KD-2 are about whether the
committed bytes can be checked, not about whether they should be there.

## 7. Inventory declarations

None required. All five claimed files are already in
`index.extra_hashed_inputs` and in `coverage.governed_scope`, declared by the
pilot's dashboard block on 2026-09-19. This is the second spec in the sequence
that needs no `spec-spine.toml` change, after `012`.

## 8. Out of scope

- **Every repair**, including the one-line `kit.version.name` fix.
- **Rebuilding and committing the artifact.** D-1.
- **Adding a drift check to CI.** W-19, and an enforcement decision.
- **`hiqlite/static` itself and its place in the denominator.** F-016, W-14,
  blocked on the pinned tool.
- **The dashboard's behavior and its authorization boundary.** `018`.
- **`@sveltejs/kit`, `vite` and `rust-embed`**, named as pinned dependency
  behavior.
- **Ratification, enforcement, and any tool or pin change.**
